# 活动特效与对地特攻：口径与出处

2026-08-07 为修胜率预测而做的溯源记录。这里只记「谁说的、怎么算」，不放数据本身——
原始文件按矿脉纪律不入库（`assets/review/*.raw.*`、`*.wikitext.txt` 已 gitignore）。

起因：62-4 X 点的预测 S/A 10%，实际打出 12/12 全灭的完美 S。拆开发现我方总输出的
72% 来自模型完全看不见的机制（对地特攻 54% + 基地航空 12% + 夜战 7%），
另有约 9% 是活动特效倍卡。

## 源与获取方式

全部走原始接口取原文，**不经任何模型转述**——用 WebFetch 试过一次，
小模型把 `1.7063~1.7064` 这类值压成 `1.03-1.38` 的范围，还自称「摘要」。

## 已确认的计算口径

### 一、活动倍卡

页面原文：「全图倍卡、点位倍卡、舰种倍卡与分组倍卡分别计算；同一舰娘同时满足多个条件时，**各项补正叠乘**」。

**倍卡不分难度**——难度只影响解谜条件与资源基础值。拿丙难度资料包逐条核对过
（驱逐 1.04、X点重巡 1.13、英 1.15、Gloire 1.6432 全部一致）。

解析判据在 `scripts/lib/event-bonus.mjs`，三个坑见该文件头部与 `test/event-bonus.test.mjs`。

### 二、海外舰载机 / 陆航特效

```
合計倍率 = A組全マップ倍率 × A組特定マス追加倍率 × B組特定マス倍率
```

- 舰上攻击只吃 A、B 组；基地（陆航）只吃 C 组。一件装备可同属多组，
  算舰上倍率时它的 C 组归属无效，反之亦然。
- 同组不重复：两件都属 A1 只算一次 A1。所以凑特效要尽量塞**不同**的组。
- 搭载归零则该件的倍率消失。
- 分级表逐件标注 A1~A3 / B1~B4 / C1~C3 归属，CSV 结构化，直接可解析。

### 三、对地装备特攻

```
補正 = 上陸用舟艇ベース × 上陸用舟艇改修平均補正 × 上陸用舟艇個別補正
     × 内火艇補正 × 内火艇平均改修補正 × 他の装備補正
```

最容易写错的一处：上陸用舟艇ベース 只算一次，不是每件登陆艇各乘一次。原文举例：

```
大発動艇 + 大発動艇(八九式中戦車&陸戦隊)
  = 1.4 × 1.2        ✓
  = 1.4 × 1.4 × 1.2  ✗
```

另有 `一式砲戦車 = 八九戦車 + 11連隊 + 自身` 这类等价展开规则。
改修补正：内火艇 `1 + 平均改修★/30`，登陆艇 `1 + 平均改修★/50`（只算一次）。

倍率**全部是 cap 后补正**；装备特效在雷击阶段无效（船渠棲姫是例外，它吃）。

### 五、通用对地特攻表 — 首选 kcwiki「对陆补正」

同域两个源都看过，kcwiki `对陆补正` 页更适合做数据源（这是倍卡之外，
第二处 kcwiki 优于 wikiwiki 的地方，理由是形态而非新鲜度）：

- 一张总表横向覆盖全部类型（砲台小鬼 / 離島棲姫 / 港湾棲姫・北方棲姫・飛行場姫・集積地棲姫 /
  港湾夏姫 / 集積地棲姫阈值后），wikiwiki 是每类一张分散的表；
- 列头直接写明 「集積地棲姫（III バカンスmode以外）」——本次那个
  集積地棲姫II 的归类有了直接出处，不必再靠伤害比反推；
- 阈值前/阈值后补正在同一张表里标清位置，公式段也完整。

页面自己提示「下表的补正可能不会及时的更新」并指向梦美老师的 NGA 帖

本项目不绕过访问限制，所以以 kcwiki 这张表为准。

舰种补正只有两条：驱逐・轻巡对砲台小鬼 ×1.4；潜水舰对所有陆基 **+30**（加算）。
揚陸艦（stype=17）不在其中——第百一号輸送艦改的高伤害不是舰种加成来的。

以下 wikiwiki 那份仍保留作交叉核对。

### 五之二、wikiwiki「対地攻撃」（交叉核对用）

陆上型分六类，每类一张倍率表：ソフトスキン型 / 集積地型 / トーチカ型(砲台小鬼) /
ハードスキン型(離島棲姫) / 特殊型(港湾夏姫・北端上陸姫) / 浸水型(水上艦)。
同一件装备对不同类型的倍率差得很远，不能用一套值套所有陆上型：

| | 集積地型 | トーチカ型 | 港湾夏姫 |
|---|---|---|---|
| 三式弾 | ×2.5 | **×1.0（无效）** | ×1.75 |
| WG42（1积/2积） | 1.3 / 1.82 | 1.6 / 2.72 | 1.4 / 1.68 |
| 大発動艇 ベース倍率 | **1.4** | **1.8** | **1.7** |
| 特二式内火艇（1积/2积） | 1.5 / 1.8 | 2.4 / 3.24 | 2.8 / 4.2 |
| 陸戦隊・一式砲戦車・III号系 | 1.5 / 1.95 | 1.5 / 2.1 | 1.6 / 2.4 |

补正的应用顺序（原文）：

```
艦種補正 ⇒ 一般対地乗算 ⇒ (11連隊・M4A1 等特殊補正) ⇒ WG迫撃砲加算 ⇒ キャップ後補正
```

多件装备时，`一般対地乗算補正`、`WG迫撃砲加算補正`、`集積地補正` 这三者**各自求值后再合算**；
满足多个条件时全部乘算/加算。改修补正：内火艇 `1+★平均/30`，
登陆艇 `1+(上陸用舟艇★平均 + 特四式内火艇系★平均)/50`。

部分条目标着「昼のみ」（武装大発・装甲艇、特四式内火艇 2 积等），夜战不吃。

### 六、基地航空队攻击力（wikiwiki「基地航空隊」）

```
基本攻撃力 = 種別倍率 × {(雷装 or 爆装 + 改修強化値) × √(搭載数補正 × 搭載数) + 25} × 陸偵補正
最終攻撃力 = [[基本攻撃力] × クリティカル × 熟練度クリティカル]
           × 触接 × 陸攻補正 × 陸攻特効 × 敵連合特効
```

- 種別倍率：陸攻 **0.8**、大型陸上機/艦攻/艦爆/水爆 1.0、噴式機 0.7071
- 陸攻補正 **×1.8**；敵連合特効 对联合舰队 **×1.1**、对通常 1.0
- 改修強化値：陸攻・大型陸上機 `0.7×√★`
- 熟練度クリティカル補正 1.0~1.2
- **航空战不受 cap 前补正**——交战形态、阵形、损伤补正一律不影响。这条很关键：
  预测里陆航那一段不能跟着昼战一起乘交战形态系数。
- 打水上舰用雷装，打陆上型用爆装（陆攻对陆上型时雷装完全不参与）

对陆上型的完整式（「対地攻撃」页）：

```
キャップ前攻撃力 = 基本攻撃力 × 基地航空特効(砲台・離島姫)
最終攻撃力 = [[[キャップ後攻撃力 × 爆撃特効(集積地) + 基地航空特効(集積地)]
             × 爆撃特効(砲台・離島姫)] × クリティカル × 熟練度クリティカル]
             × 触接 × 陸攻補正 × 陸偵補正 × 敵連合特効
```

`基地航空特効` 与攻击队种类无关，`爆撃特効` 只有艦爆・陸攻能得。

## 两处查证结论（2026-08-07）

### 一、陸戦部隊（type2=52）：第百一号輸送艦系列独占，倍率在该舰专页

一度以为这是上游空洞（wikiwiki/kcwiki 的通用对地页都查不到，三源核查全无）。
结论是错的——找错地方了。它是单舰独占机制，通用页不会为一艘舰单列一类，
数据在 wikiwiki 的 `第百一号輸送艦改` 页上。

独占范围（游戏主数据实证）：`api_mst_equip_ship` 里全游戏只有 2 艘能装 type2=52：

```
mst727 第百一号輸送艦改   {"1":[...],"4":[...],"12":null,…,"46":null,"52":null}
mst945 第百一号輸送艦     {"1":[...],"15":null,…,"46":null,"52":null}
```

两条都值得注意：`api_mst_stype` 里**没有任何舰种**标记可装 52（连揚陸艦都是 ×），
靠的是单舰矩阵覆盖；而矩阵里**没有 24**——所以这两艘装不了大発系
（wikiwiki 原文：「大発系（上陸用舟艇）は装備できない」）。
其他揚陸艦（秋津洲・あきつ丸）装不了 52。

倍率（対集積地棲姫系のキャップ後補正）：

| 装备 | 个数 | 倍率 | 累积 |
|---|---|---|---|
| 陸戦部隊 | 1个目 | **×3.15** | ◯ |
| | 2个目 | ×2.35 | ◯ |
| | 3个目 | ×1.2 | ◯ |
| チハ改 | — | ×1.2 | ✗ |
| 陸軍歩兵部隊 | — | ×1.55 | ✗ |

哪件吃哪项：

| 装备名 | 陸戦部隊補正 | チハ改補正 | 歩兵部隊補正 |
|---|---|---|---|
| 陸軍歩兵部隊 | 〇 | - | 〇 |
| 九七式中戦車(チハ) | 〇 | - | - |
| 九七式中戦車 新砲塔(チハ改) | 〇 | 〇 | - |
| 陸軍歩兵部隊＋チハ改 | 〇 | 〇 | 〇 |

页面给的计算例（原文照录）：

```
陸軍歩兵部隊＋チハ改 + 九七式中戦車 新砲塔(チハ改) + 特二式内火艇★max
  = 3.15(陸戦部隊1個目) × 2.35(2個目) × 1.2(チハ改) × 1.55(陸軍歩兵部隊)
    × 2.267(特二式内火艇★max の集積地補正) = ×31.209
陸軍歩兵部隊＋チハ改 + 九七式中戦車 新砲塔(チハ改) + 九七式中戦車(チハ)
  = 3.15 × 2.35 × 1.2(3個目) × 1.2(チハ改) × 1.55(陸軍歩兵部隊) = ×16.522
```

本机实测吻合：那一场第百一号带 チハ + 陸軍歩兵部隊 + 特四式内火艇，
按上表 `3.15 × 2.35 × 1.55 = ×11.47`（陸戦部隊 2 件，チハ改補正不适用）。
实测它对集積地棲姫II 打出 3348、同轮夕張改二特（type2=24 装备）354，差 9.5 倍——量级对得上。
而这个补正**只对集積地棲姫系**生效，所以同一艘舰同一场打港湾夏姫II 只有 **127**。整条链自洽。

建模要点：这是**キャップ後補正**，且「陸戦部隊」按件数累积、「チハ改」「歩兵部隊」
各自只算一次（不累积）；判定必须按 type2=52 而非名字（见下）。

### 二、集積地棲姫II（2016）走「集積地型」表 —— 已有直接出处

kcwiki「对陆补正」总表的列头直接写着「集積地棲姫（III バカンスmode以外）」，
II 属于「III 以外」，归类到此为止，不必再靠推断。以下为拿到出处之前的实测推理，
保留作交叉验证。

wikiwiki 的分类原文是「集積地型 … 集積地棲姫」，整族归集積地型；
`集積地棲姫III バカンスmode`（2138~2145）被单列进「浸水型(水上艦)」是例外，
搬运贴也写明 III「以前の集積地棲姫と特性が異なる」。页面里没有 II 的条目。

本机实测两条硬证据（战斗快照 #149，第百一号輸送艦改）：

| 攻击 | 目标 | 伤害 |
|---|---|---|
| 主力炮击第一轮 | 集積地棲姫II | **3348**（一击击沉 1200 HP） |
| 主力炮击第二轮 | 港湾夏姫II | **127** |

1. 它被百一号优先攻击 —— 搬运贴说 III 因为「実質水面敵単位」不会被百一优先打，
   II 被优先打了，排除浸水型。
2. 同舰同装备对两个目标差 26 倍 —— 正是「集積地型有 cap 后补正、港湾夏姫只有 cap 前」
   的特征（分类原文：集積地型「ソフトスキン型と同様の耐性に加えて…キャップ後補正が有る」）。

# 夜战（2026-08-08 核对）

来源：wikiwiki「夜戦」与「戦闘について」。逐条抄录，实施在 `src/shared/night-battle.ts`。

| 项 | 口径 | 关键 |
|---|---|---|
| 基本攻撃力 | 装備込み火力 + 装備込み雷装 + 改修強化値(夜戦) + 夜間触接定数 | **没有昼战炮击那个 +5 常数** |
| キャップ | **360**（2021-03-01 由 300 上调） | 昼战 砲撃 220 / 雷撃 180 / 対潜 170——同页核对，与本仓库昼战模型现用值一致 |
| 陣形補正 | 「原則受けません」 | 唯一例外：「※警戒陣のみ主力艦の威力が半減(0.5倍)する」 |
| 交戦形態補正 | 「原則受けません」 | 例外：開幕夜戦の対潜攻撃 |
| 連合艦隊 | 「連合艦隊の第1艦隊は夜戦に参加しない」 | 只有第二舰队出手 |
| 大破 | 「大破状態の場合」攻撃できない | |
| 空母 | 「火力と雷装の初期値がともに0の艦娘は夜戦攻撃が行えない」 | 用 stype 判，不能用最终面板判 |

## 改修强化值与昼战的差别

只有一处但会咬人：声呐 / 爆雷投射机 / 大型声呐不参与夜战炮击（它们是对潜装备），
而**探照灯参与**（√★）。照抄昼战那张表会把带满声呐的驱逐虚报一截。

## 刻意不建模的

- 夜战 CI（主主 / 魚魚 / 魚見魚 …）：发动率取决于运、探照灯、照明弹、旗舰位置与损伤，
  方差极大。与昼战的弹着观测同一条纪律——不套一个 1.2~1.75 上去冒充确定值。
- 夜間触接（+5/+7/+9）：要判敌方制空与夜偵搭载。
- 夜战空母（Saratoga Mk.II、赤城改二戊 等）：要单舰白名单 + 夜間作戦航空要員 +
  夜間飛行機 三者共同判定，`ForecastShip` 没有这些字段，因此**一律不让空母夜战**。宁可少算。

三项都写进说明栏的「未计入」，不偷偷少算。

## 两处近似（模型自身的，不是游戏规则）

- 敌方夜战输出按 `surviving = 1 − 昼战压制度` 打折。不折就等于假设敌队整队完好地进夜战，
  大破风险会被系统性高估。副作用是正确的：昼战就能全歼时 surviving→0，夜战不再增加风险。
- 昼夜两段视作独立的风险暴露，按 `1 − (1−昼)(1−夜)` 合成——与 `taihaChance` 内部
  跨舰连乘 `allSafe` 是同一个道理，不另发明系数。

# 弾着観測射撃（2026-08-08 核对）

来源：wikiwiki「戦闘について」的弾着観測射撃项。实施在 `src/shared/day-spotting.ts`。

## 前提（四条全部满足）

1. 航空戦で航空優勢または制空権確保
2. 攻撃艦の損傷が中破以下（＝不是大破）
3. 攻撃艦が主砲+αを装備
4. **搭載数 1 以上**のスロットに水上偵察機か水上爆撃機

第 4 条的「搭載数 1 以上」容易漏：空格里的水侦不算数。

## 种别 · 倍率 · 観測種別定数

| 种别 | 主砲 | 副砲 | 徹甲弾 | 電探 | 倍率 | 定数 |
|---|---|---|---|---|---|---|
| 主砲+主砲 CI | 2 | — | — | — | 1.5 | 150 |
| 主砲+徹甲弾 CI | 1 | — | 1 | — | 1.3 | 140 |
| 主砲+電探 CI | 1 | — | — | 1 | 1.2 | 130 |
| 主砲+副砲 CI | 1 | 1 | — | — | 1.1 | 120 |
| 連撃 | 2 | — | — | — | **1.2 × 2 回** | 130 |

連撃写成「2.4 倍一次」是错的——它是两次各自判命中的攻击。

## 発動率

`発動率 = ⌈観測項⌉ ÷ 観測種別定数`

- 確保：`観測項 = ⌊⌊√運+10⌋ + 0.7×(艦隊索敵補正 + 1.6×装備索敵値合計 + 10)⌋ + 旗艦補正`
- 優勢：`観測項 = ⌊⌊√運+10⌋ + 0.6×(艦隊索敵補正 + 1.2×装備索敵値合計)⌋ + 旗艦補正`
- 旗艦補正 **+15**（随伴艦 +0）

装备类型编号取自本机 `api_mst_slotitem_equiptype` 实核：
1/2/3 主砲、4 副砲、10 水上偵察機、11 水上爆撃機、12/13 電探、19 対艦強化弾。

## 已知偏低（刻意的）

`艦隊索敵補正` 按 0 处理。查了三处：wikiwiki 只写「艦隊索敵補正」不给定义；
ぜかましねっと明确写着这一项「記載なし」，只说「艦隊全体での索敵の数値が高いほど
発動率は大きくなる ※艦娘の素の索敵値」。素索敵值这个量本仓库本来就不推导
（`MasterShip` 的注释：回避/对潜/索敌的基础值随等级插值，反推会失真故不做）。

所以这一项少算，不编。装備索敵値合計、運、旗艦補正三项都照式子算，
所以带水侦电探的舰仍然吃得到大部分收益。界面上这一层挂虚线并写明「偏低」。

多种别同时满足时（主砲2+徹甲弾 既能主主也能主徹）按倍率降序依次条件掷骰——
**掷骰顺序是本模型的假定**，来源没写清优先级。

# 基地航空队：对空射击回避与行动半径（2026-08-27 核对）

来源：wikiwiki「対空砲火」`#avoid_AAfire`（最终编辑 2026-08-17）与「基地航空隊」
（最终编辑 2026-08-06）。两页都取的原始 HTML 字节，实施在
`src/shared/lbas-radius.ts` 与 `src/shared/lbas-recommend.ts`，事实表是
`assets/lodes/equip-aa-evasion.json`。

## 又一次证明本文开头那条纪律

半径公式我一度用转述层取过一遍，拿回来的是一句**原页面里并不存在**的话。
拉原始 HTML 再 grep 才找到真句子——它躲在 `<span class="wikicolor">` 里，
而且 `＋`/`－` 是**全角**、`√` 是字面字符（不是 `&radic;` 也不是 `sqrt`），
按半角符号搜必然落空。取数值一律拉原始字节，别信任何转述层。

## 一、行动半径

页面自己标的是「出撃可能範囲の**推定式**」——社区推定，不是官方公布值：

```
出撃可能範囲 ＝ 航空隊の最低戦闘行動半径 ＋ √(航空隊の偵察機の最大戦闘行動半径 － 航空隊の最低戦闘行動半径)
※小数点第１位以下を四捨五入   ※最低行動半径からの加算は最大3まで
```

四条配套原文事实：

- 「航空隊の4つの中隊のうちで最も短い戦闘行動半径の値が、その航空隊の出撃可能範囲となる。
  **0機になっている中隊は除外される**」
- 能延伸的只有四个机种：「大型飛行艇・艦上偵察機・水上偵察機・陸上偵察機を組み込むことで
  延伸が可能。水爆・水戦含め他の機種では延伸不可」
- 「延長する側の偵察機自体は延長できない」——结果不会超过那架侦察机自己的半径
- 「一式戦 隼II型改(20戦隊)・一式戦 隼III型改(熟練／20戦隊) 以外の、**回転翼機・対潜哨戒機**が
  配備されている場合、**延長効果自体が無効になる**」

同页附了一张实例表（六种侦察机 × 最低半径 1..10 的结果），已逐格写进
`test/lbas-recommend.test.mjs` 当预言机——公式改错了那张表会先红。

### 一个源间冲突，已裁

kcwiki 把最后那条写成那些机体「不可**被**提升航程」（只是自己享受不到），
wikiwiki 写的是「延長効果**自体**が無効になる」（整队的延伸都没了）。两说不等价。
**裁给 wikiwiki**，判据是它自己脚注 *3 给的反例：
「半径1の秋水と半径2のS-51がある場合、偵察機を配備しても**半径2止まりにすらならず半径1のまま**となる」
——若按 kcwiki 的读法，S-51 停在 2、秋水被延伸，全队应得 2；实际是 1，只有「整队失效」解释得通。

### 一个反直觉处，别按名字猜

東海（試製東海 269 / 東海(九〇一空) 270）在主数据里是 `api_type[2]=47 陸上攻撃機`，
不是対潜哨戒機——它**不**让延伸失效。真正落在対潜哨戒機(26) 里的只有三式指揮連絡機族
与两件一式戦 隼(20戦隊)，而后两件正是原文点名的例外。所以判据要走 type2 + 那两个 mstId。
（另：wikiwiki 自己在対潜哨戒機表里把 491 写成「隼**II**型改(熟練/20戦隊)」，
正文与回避表写的是 **III**，主数据也是 III——照主数据。）

## 二、中队定数与配置耗铝

原文：「偵察機系(水偵/艦偵/**大型飛行艇**/陸偵)は1スロットに **4機**、
大型陸上機は1スロットに **9機**、それ以外は1スロットに **18機**」。
**二式大艇是 4 机不是 9 机**（它算偵察機系），照「大型機」字面猜会错。

配置耗铝 = `api_cost × 该格定数`。上游给的实例与主数据自洽：
二式大艇 25×4=100、Catalina 13×4=52、深山 20×9=180、一式陸攻 12×18=216、
一式陸攻(八幡部隊) 5×18=90、東海 9×18=162（这条反过来又印证了東海按陸攻算 18 机）。

配置、补充、出击是**三套**互不相同的消耗，别混：配置吃铝；补充
`燃料=喪失機数×3 / ボーキ=喪失機数×5`（没损失就不消耗）；出击只吃燃料与弹药，不吃铝。
现有 UI 那句「配置消耗 铝N/机」只对**配置**这一次，措辞成立。

## 三、对空射击回避

```
加重対空値(補正後) = [加重対空値 × 加重対空補正]
艦隊防空値(補正後) = [艦隊防空値 × 艦隊防空補正]
```

综合档位 **❀ > ☆ > ◎ > ◯ > △**（符号是那两个数的综合评价，不是第三个独立量）。
实际取值只有五组：❀ 0.4/0.4（全游戏只有 Ho229）、☆ 0.5/0.5、◎ 0.5/0.7、
◯ 0.6/0.7、△ 0.6/1.0。**△ 削不动艦隊防空値**，与 ◯ 不是一回事，排序里别并档。

它确实作用于基地航空队，三条独立证据：①表里整整一节是 陸上攻撃機，而陆攻是
「基地航空隊にのみ装備可能」；②「一式陸攻(野中隊)」页脚注给出同样的 0.6/1.0；
③同页正文「基地航空隊は…とにかく損耗が発生しやすい。その為、射撃回避特性を持つ
本装備の優位性は、相対的に見て大きい」。没有任何源说它只对舰载机生效。
（相邻但**无关**的一条：基地航空队不吃敌方対空カットイン。）

### 置信度：整张表单源，别以为条目多就硬

转述这张表的几家（zekamashi / kitongame / kankorekore）都是同一张 wikiwiki 表的转录，
不构成第二票；kou-ch-ac 是**街机版**（机制不同，绝不可并表）；
en.kancollewiki 撞 Cloudflare 机器人挑战页，未取证也未绕过。
所以事实表的 `basis` 一律写「单源待印证」。唯一的机器侧交叉校验是：
47 行机体名**全部**能在游戏主数据里按名对上（0 条落空）——那只证明誊抄没串行，不证明数值对。

**不在表里 ≠ 弱档**：一式陸攻、銀河(无印)、四式重爆 飛龍(无印)、深山、東海、二式大艇 等

# 基地航空队：按目标类型的有效威力（2026-08-27 二期核对）

来源：wikiwiki「基地航空隊」（与一期半径/回避档同一次抓取的同一份原始 HTML 字节）。
实施在 `src/shared/lbas-target-power.ts`，预言机在 `test/lbas-target-power.test.mjs`。

起因是推荐搭配一期的威力列直接拿裸雷装/爆装排序，太粗——同一架飞机打水上舰、
打砲台小鬼、打離島棲姫、打集積地棲姫，倍率与补正**位置**都不一样。

## 一、対地特効表（原文那张三行表照抄）

| 補正種別 | 基地航空特効 | 爆撃特効 |
|---|---|---|
| 砲台小鬼 | ×1.6 | ×1.55 |
| 離島棲姫 | ×1.18 | ×1.7 |
| 集積地棲姫 | **+100（加算）** | ×2.1 |

- 集積地那一格是加算，上下两行是乘算。照着上下行想当然写成 ×100 差两个数量级。
- 「基地航空特効は攻撃隊の種類に関係なく得られる補正」——**所有机种都吃**。
- 「爆撃特効は艦上爆撃機、陸上攻撃機が得られる補正」——**只有这两类**。
  同段紧接着「水上爆撃機や、噴式戦闘爆撃機も同様の補正を受けると思われるが未検証」，
  是上游自标的未检证，所以本仓库**不给**水爆与噴式戦闘爆撃機。宁可低估。
- 施加位置两类不同：砲台小鬼・離島棲姫 是「基地航空特効が火力キャップ前に、
  爆撃特効が火力キャップ後に」；集積地棲姫 是「基地航空特効、爆撃特効共に火力キャップ後に」。

## 二、キャップ值：上游正文说 220，上游自己的表算的是 150——裁给表

同一页正文写「※下線部に火力キャップ(キャップ値220)が適用される」，
但同页附的三张攻撃力比較表（対砲台小鬼／対離島棲姫／対集積地型，陸攻 11 行 + 艦爆 3 行 ×3 = 42 格）：

| キャップ | 42 格里对上几格 |
|---|---|
| **150** | **42 / 42** |
| 170 | 37 / 42 |
| 220 | 37 / 42 |
| 不设 cap | 37 / 42 |

差异只出现在高爆装机体上，那正是唯一能把几种读法分开的地方。逐格算例：

```
Do 217 K-2＋Fritz-X（爆装24）対砲台小鬼，表上 437.4
  基本 = 0.8×(24×√32.4+25) = 129.29 ；×1.6 = 206.86
  cap150 → 150+√56.86 = 157.54 → ⌊157⌋ ×1.55 = ⌊243⌋ ×1.8 = 437.4  ✔
  cap220 → 未触顶 206.86        → ⌊206⌋ ×1.55 = ⌊319⌋ ×1.8 = 574.2  ✘
```

**裁给表**：表是 42 格逐格的数值证据且自洽，正文那句只是一句话。
那句 220 很可能是从上一节「対水上艦」搬下来的——那一节原话是
「基本攻撃力に火力キャップ220が掛かるが、**ほぼ到達不可能**なので実用上気にする必要はない」，
対水上艦的基本攻撃力上限约 88，确实到不了，所以那一节写 220 不影响任何数。

42 格全部进了回归测试当预言机，`LBAS_LAND_POWER_CAP` 改一个字那批测试立刻红（已变异验证）。

## 三、下取整的位置——一期漏了一处

対水上艦的 `最終攻撃力 = [[基本攻撃力] × クリティカル …] × … × 陸攻補正 …`，
里层那个 `[]` 是对基本攻撃力下取整，然后才乘陸攻補正。同页「最終攻撃力比較表」
16 格（陸攻 8 + 大型陸上機 2 + 艦攻艦爆 5，含 雷装0 那一行）**逐格验证 16/16**。

一期没有这个下取整，所以一期显示的 Mosquito FB Mk.VI 是 77（未取整的 76.98），
上游表写的是 **75.6**。二期补上，数值与上游表逐格一致。

> 注：`landBaseWavePower`（战斗页的战斗预测那条路）**没有**跟着改。它按「陆上目标占比」
> 混合加权，对一个混合值下取整是假精度；而预测那边是跨多波求和，不到 1 的差是噪声。
> 推荐搭配这条路走的是 `squadronPower`，逐中队各自取整，与上游表对得上。

## 四、陸偵補正在两条式子里的位置不一样

- 対水上艦：陸偵補正在 `基本攻撃力` **之内**（下取整之内）
- 対地　　：陸偵補正在 `最終攻撃力` **末尾**（下取整之外）

抄成同一处，带二式陸偵的队会差一点点。有专门的护栏钉着。

## 五、两处「查了，确实没有」——别再去找第二遍

按「说没有之前先穷举」那条纪律记下来，省得下次重查：

- 反跳爆撃（跳弹轰炸）不是本作的机制。 `反跳` / `跳弾` 两个词在
  「基地航空隊」与「対地攻撃」两页的原始 HTML 里各出现 **0 次**。
  游戏自己的装备分类（`api_type[2]`）里也没有对应类目。
- 「火箭弹机」在陆航这边没有独立类目。 「対地噴進砲」族（WG42 / 四式20cm対地噴進砲）
  是**舰装**，倍率早已在 `src/shared/anti-land.ts` 里；陆航侧带「誘導弾」的那几件
  （Do 217 E-5＋Hs293、四式重爆 飛龍＋イ号一型甲 等）在机制上就是高爆装的陸攻，
  不另立类目、不另给倍率。

所以「机种 × 目标类型」的真实两维是：
**机种**（種別倍率 / 陸攻補正 / 吃不吃爆撃特効 / 用雷装还是爆装）
× **目标**（水上舰 / 砲台小鬼 / 離島棲姫 / 集積地棲姫 / 其余陆上型）。

## 六、刻意没建模的两项

- 命中：上游原话「命中率やクリティカルヒット発生率についてはデータ不足であり要検証」
  ——基地航空队的命中率公式**上游没有**。装备表里那一列「命中」是装备面板值，不是命中率，
  拿它当命中率排序是编数。界面上照实写「命中未计入」。
- 陸攻特効（対水上ボス）：原文只说「陸上攻撃機による一部の水上ボスに対する特効は
  式の最後にかかる」，举的例子还是个区间（「空母棲姫に対する倍率は3.2～3.4倍程度」）。
  按敌人逐个给、没有通用表，不进模型。

## 七、装甲减算（穿甲）为什么没进推荐排序

伤害 = 攻撃力 − 装甲（含装甲乱数），装甲是逐个敌人的减数而不是乘数：
两架飞机威力差 20，打任何装甲的目标都还是差 20，名次不会因为装甲改变。
所以把装甲接进来**不会改变推荐次序**，只会把同一个次序整体下移。
真正会翻盘的是「威力低到被装甲吃光」，而那一档在本模型里早被
「打不动的整个排除」那道闸挡掉了。另外陆航主要用在活动图，而
`map-enemy-comps` 只覆盖 37 张常规图，活动图没有点位敌编成——
硬接等于对着空数据编。故不接，界面也不暗示有。

  条目形如 `by: 'lbas'` / `key: 'C2'` / `scope: 'P1 Boss（D点）'`。
- 分组名单（哪架飞机属于哪个 C 组）在另一个页面上的另一张表
  → 新建的 `event-plane-groups` 包。

两半各自换期、各自更新，合在一处会让「倍率更新了但名单没动」这类半新半旧无处安放。
运行时靠期号对齐：分组表的 `data.event` 与倍卡包 URL 里的 `page=` 不一致就整表不生效。

## 二、机制三条（两家原文一致）

1. 整队倍率。kcwiki 原话「陆航倍卡对**所在队伍中的 4 架飞机**全部生效」；
   wikiwiki 的計算例把它算成一个作用于整队的系数
   （「基地にSM.79 bis(熟練)+B-25 の場合(C2+C3)：1.06 × 1.03 ≒ 1.09」）。
   这一条是三期全部改动的起点——队里塞一架特効机，另外三架的伤害也一起涨，
   于是「取前四强」不再等于最优，排序口径必须从单机择优变成组合择优。
2. 同组不重复，异组叠乘。队里两架都是 C2 也只乘一次 1.06；C2 与 C3 各一架才是
   1.06×1.03。wikiwiki 原文「異なる倍率の組同士を乗算。同じ組の倍率は重複しない」。
3. 舰上只吃 A/B 组，基地只吃 C 组。一件装备可同属多组（例：Loire 130M 同属 A1/B3/C2），
   装在舰娘身上时它的 C 组归属无效，放进基地时 A/B 归属无效。所以本表只收 C 组。

另有一条**刻意没建模**的：「搭载数归零则该件特効失效」。推荐搭配规划的是出击前的满编配置，
四格都是满的；打到一半掉光是战斗中的事，不属于「该配什么」这个问题。

## 三、名单的置信度：两家一致，但不是两票

名单核过两家、37 件（C1 两件 / C2 十九件 / C3 十六件）逐行完全一致：

- wikiwiki 活动页 `反撃！第三十一戦隊の戦い/E4`、`/E5` 的「航空機特効」表
  （表头原文 `基地` + 下标 `c`，列 C1/C2/C3；E4 与 E5 两页的分组段互为副本，也逐行一致）
- kcwiki《2026年夏季活动海外舰载机倍卡分组》

但两家都自述转自同一份社区分类表——wikiwiki 写「航空機の分類については こちら を参照
（08/01確認）」、kcwiki 写「资料来源：海外艦載機/基地特効分類2026 V0.9」，
两个链接指向同一个 Google 表格 id（`1xLQCPWCKjawi3Kh_LMKPxJmbGnJ2thOOgfm_xORGr3M`，
自称最终更新 2026.07.28）。按本仓库既有的算票纪律，这属于**同源转录**，不是多源印证：
一致只证明誊抄没串行，不证明上游那张表本身对。故整表 `basis` 写「同源转录」，
护栏里另有一条断言挡着它被改写成「多源/双票」。要升格只能靠账本实测。

37 件另逐条对过游戏主数据 `api_mst_slotitem`，全部按名命中、0 条落空——
这同样只证明誊抄没串行。

## 四、两个解析坑（都踩过，都会让组别读错而不报错）

- kcwiki wikitext：`|}` 是表尾，不是单元格。按「行首 `|`」收集单元格时会把它当成一格，
  于是**每张表的最后一行**整体错位一格。本期正好把 `Do 17 Z-2`（C3→读成 C2）、
  `Mosquito PR Mk.IV`、`Ho229`（C2→读成 C1）三件读错。
- wikiwiki HTML：rowspan 的额度要在本行就扣。晚扣一行会让「機種」列失效的那几行整体左移，
  同样错组（`Do 17 Z-2` 与 `Ho229` 这两行正是 rowspan 结束处）。

两个坑的共同点：错位之后**每一行仍然是合法数据**，没有任何异常可报。
所以护栏不是「解析成功」，而是「同一件装备不许落进两个 C 组」（schema 级）
加上三件已知踩过的逐件钉死（`test/lbas-event-bonus.test.mjs`）。

## 五、点位（scope）怎么认——本期有两处会读错

上游同一列里混着两种写法，还会用换行混在同一格：
「**阶段名 + 点位**」（`P3 Boss（S点）`）与「**裸点位清单**」（`K、K1、K2、L` / `P3`）。
判据改成**逐行**来：这一行出现了「X点」/「Xマス」就只认它标出来的点，否则整行按顿号拆。

本期两处非这么分不可（原来那版子串匹配两处都错）：

- 阶段 P2 与点位 P2 同时存在。 `P2 Boss（J2点）` 指的是 J2；一律按裸清单读会把这一行的
  倍率错发给点位 P2（E5 确实有 P2 点，行动半径 8）。
- 点位 Z 与点位 ZZ 同时存在。旧判据用 `scope.includes('Z点')`，而 `"ZZ点"` 里**含有**
  `"Z点"`——于是 P4 Boss（ZZ点）的一整套倍率被错发给了 Z 点。这是接三期时才发现的既有缺陷，
  逐点重放实测：E5 的 Z 点原本会多吃到 13 条不属于它的条目（7 条舰种 + 5 条国籍 + 1 条舰载机）。

顺带修好的另一半：`P3`、`L1`、`L2` 这类**裸点位**写法原先一条都匹配不上，
于是全部点位条目在 E1–E3 与 E5 的一大片点位上静默失效（重放实测新命中 291 条）。
本期 E5 的陆航特効正好有三个点（P3、L1、L2）落在这种写法上——不修就等于告诉玩家那三个点没有特効。

判据是**共用**的（`shared/event-bonus-apply.ts` 的 `scopeApplies`），
所以战斗页的舰娘倍卡与活动页的陆航推荐同时受这次修正影响，两边说的话一致。

## 六、组合择优与用户原序怎么衔接

用户定死的三级排序「①回避档 → ②威力 → ③耗铝」是给**单机**排的。
三期用户要的是「候选组合里含 C 组机的与纯强机组合比**全队总有效威力**，取真最优」。衔接：

- 组合层面以总有效威力为主序（含整队特効倍率）；
- 落在 **0.5% 相对带宽**之内视为打平，交回原来那把尺子逐格比（回避档 → 威力 → 耗铝）
  ——即用户说的「同总威力附近优先保机组合」；
- 单机层面档位一字未动：仍是显示键、仍是同分决胜键，`compareCandidates` 没有改。

带宽取 0.5% 的理由：够窄，不会让明显更强的组合输给保机组合（E5 那组相差 4.3%）；
够宽，不至于因为浮点尾数永远判不成平手。

枚举是精确的：候选池先做一遍「被支配就删」（同机种同组归属下，威力/半径/耗铝/回避档
四项都不更差且持有数足够铺满整队的那件，可以整件顶替被支配的那件），删掉的不可能出现在最优解里。
剩下的全枚举。实测把整个游戏的合格机体全塞进来（每款 4 件）裁完是 50～57 件，都在上限 64 以内
——也就是说近似那条路在正常仓库里不会走到；真走到了方案上会标 `approx`，界面照实写「近似」。

## 七、非活动语境的隔离

用户的硬性要求：目标点不是活动图就走纯二期逻辑，**零特効因子、零组合择优**。
落法是两条独立的路，由 `input.bonus` 分岔——`recommendPlain` 是二期原函数，一个字没动。
护栏是**金样本逐字节比对**：`test/lbas-plain-golden.json` 的 420 组（7 种库存 × 5 种目标档
× 6 种半径 × 有无档表）是在特効一行都还没接之前、用二期的 dist 采的，
逐字段（含每格威力的完整浮点尾数）比对。变异验证：把分岔去掉让非活动也走组合择优 → 当场红。
