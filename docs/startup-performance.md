# 启动主数据处理优化 · 2026-09-07

同一份真实 `api_start2/getData` 主数据，在隔离 Electron 实例中回放五次，处理耗时中位数由 **360.9 ms 降至 140.6 ms，减少约 61%**。本轮只优化已定位的任务文本匹配开销，并修正看门狗的归因表述。

## 瓶颈与改动

起点为 `ba553e0`。生产主进程原有“归约”计时包含整个 `handleEvent`，无法区分状态更新和其后的任务、遭遇记录段、舰历处理。本轮用既有 `timeMain` 增加四个分段，保留原执行顺序、参数、返回切片与默认 50 ms 日志阈值；日志 detail 只记录 API 路径。

| scope | 处理段 |
| --- | --- |
| `api:state` | 状态归约 |
| `api:quests` | 任务引擎 |
| `api:chronicle` | 遭遇记录段 |
| `api:ship-life` | 舰历 |
| `patch`（已有） | 状态广播发送 |

第一轮分段回放定位到任务引擎耗时 346–363 ms，状态归约约 1 ms。CPU 采样的大头是 `augmentShipGroupsFromQuestText`、`foldCjkVariants` 和 `foldToken`。

改动集中在两处：

- 一轮规则重建共用舰名索引，通过字符树执行原有的最长匹配。仍然只补入任务文本独立提及且前向可达的形态；保留重名舰的全部 ID，不让“黑潮改二”误匹配“潮改二”。索引随规则上下文重建，不跨主数据或译名包更新缓存。
- 同一个候选词连续查询队名、舰名、舰种、舰级时复用归一化结果。每个上下文只缓存最近一个词，不积累全部文本子串。

## 第二轮：模块装配期间的 UI 配置读取

重启后的渲染长任务继续在独立实例中采集 CPU profile 和 Chromium timeline。按单个 `RunTask` 对齐后，最长任务主要来自模块装配，包含大量 `@electron/remote` 的同步往返。另一条首见资料回调则主要在保存滚动位置时触发整页排版。这两条不能混为同一个瓶颈，也不能从某个函数的全会话累计时间推断它属于最长任务。

### 改动

原来的 `uiGet` 先从主进程取得对象代理，再在渲染层 `JSON.stringify`。读取一个有数百个属性的对象时，属性访问会变成连续的同步 IPC。

现在 `getUiJson` 在主进程把 UI 数据转成字符串，渲染层只接收字符串并解析为本地对象。对应的写入也改为 `setUiJson`：字符串传到主进程后再解析，避免把指回渲染进程的对象代理存入配置。原有保存与 `config.set` 通知仍通过同一个 `set` 实现。

没有缓存配置值：每次读都取主进程当前状态，保留跨窗口更新、null/undefined 回退、本地副本可修改而不污染源对象等行为。

## 第三轮：离屏目录与滚动保存

图鉴目录的离屏行参与了启动排版。单独设置 `content-visibility:auto` 无效：公共滚动保存逻辑读取每个后代的 `scrollTop/scrollLeft`，会把浏览器跳过的内容重新唤醒，反而出现数百次小排版。宽度容器查询也会在启动时过晚决定是否跳过；把战斗回调的读尺寸挪到别处只改变归因位置，没有可靠减少总成本。这些试验未保留。

最终改动：

- 滚动保存继续为全部元素推进稳定编号，但对浏览器跳过的内容不读取滚动属性。导航恢复同样避免为无记录的离屏内容做归零检查；有明确恢复记录时仍执行恢复。
- 只给舰娘目录的短副标题、非收藏行启用离屏布局。内容固有高度沿用现有两行样式：`12.5×1.5 + 13×1.5 = 38.25px`，没有强制修改实际行高。
- 面板宽度在 300–620px 的单列范围内启用；副标题超过 18 个字符、收藏行、窄栏及多列保持完整布局。初次数据装入前确定模式，此后由 `ResizeObserver` 跟随宽度，卸载时退订。

## 第四轮：启动装配的同步等待与重复计算

对第三轮完成后的代码继续采样，最大渲染任务为 **305.4、310.8 ms**。同步等待最初落在等级经验实测表和首次持有记录的首次读取；删除后续重复工作后，等待位置依次转移到隐藏通知/设置面板及启动布局保存。这说明不能只盯某个函数的耗时下降，必须重新检查整个任务及其调用链。

### 保留的修改

- 在启动矿脉请求发出之前，提前装入等级经验与首次持有的既有缓存。预读不观察舰队、不产生新舰判断，也不写盘；原观察入口与旧版基线迁移保持。预读失败不会锁死经验表加载状态，后续按需入口仍可重试。
- 改造图按组件成员遍历出边，避免每个组件都扫描全图。原型标签批量查找时只建立一次前驱索引。渲染层按主数据对象身份失效缓存，升级表单独替换也会刷新档位；不再反复数全量主数据键数。
- 通知与设置隐藏时不生成页面，后台监听、通知记录、开关变更和数据接收继续工作。设置面板不重复初始化各子系统已经自行读取的七个开关，避免无意义的同步读取和清空美术缓存。
- 启动时布局与读入值一致便不重复保存；补齐默认字段、迁移及模块对账产生变化时仍保存。交互操作的即时保存入口保持原样，不引入持久化成功缓存。
