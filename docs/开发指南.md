# kuma

> 球磨的口癖，与 poi 同一种取名法。舰队收藏信息工作台——另起炉灶的新「poi」。

本文是**开发者文档**（架构、构建、矿脉维护）。玩家请看仓库首页的 [README](../README.md)，
装完之后的说明书是随包的《使用说明.md》。

三条立身原则：

1. 被动只读：只监听游戏自然产生的请求，拿不到就等，绝不主动请求。
2. 信息不孤岛：全域互链是一等公民，模块间靠事件与统一数据核心咬合。
3. 规则数据不硬编码：条件/改修/带路走版本化社区数据包，且标注来源与新鲜度。

## 模块

| 布局 | `mu` | 模块装配宿主（坞位/导航/布局持久化） | — | ✅ |
| 关联 | `link` | 全域互链 EntityLink | — | ✅ |

| 编队 | `ru` | 编队展示 | 底 | ✅ |
| 资源 | `zi` | 资源统计 | 底 | ✅ |

## 布局

游戏居中，三面环坞 + 顶栏弹窗：

| 位置 | 住着谁 | 定位 |
|---|---|---|
| 左坞 | 图鉴（含舰娘列表） | 查阅 |
| 右坞 | 战斗 · 活动 | 临战伴侣 |
| 底坞 · 下1 | 资源 | 常驻速览 |
| 底坞 · 下2 | 编队 | 常驻速览 |
| 底坞 · 下3 | 任务 · 远征 | 常驻速览 |
| 顶栏弹窗 | 回顾 · 通知 · 设置 | 随用随开，不占坞位 |

每个坞可再切成多个格并排（底坞横切成列、左右坞纵切成行），每格一套标签页。
「战斗 + 活动」这类可以两块并排看。
格标签栏的 `⊞` 把当前标签拆到新格；标签/导航条上的模块格右键选目标坞与格（含「新建一格」）。
回顾、通知与设置走顶栏按钮弹浮层（Esc 或点外部关闭），不占常驻视野。
状态与事件流只在 `KANSO_DEBUG_UI=1` 时作为诊断工具出现。

最左是**模块导航条**（按功能名列全部模块）：点亮=已装配，单击切模块（自动展开所在坞），再点收起，右键换坞/分格。
分隔条拖动实时改尺寸（游戏画面用 GPU 变换跟手，松手才真缩放）、双击折叠；`F9` 专注模式只留游戏。
布局（分格/分配/尺寸/折叠/激活页）本地持久化。

窄容器不藏内容：所有面板在窄格里改为纵向堆叠 + 可滚动（右栏/预览/规则矩阵一律保留），
宽表格给最小宽度后横向滚动，绝不裁字段。

资源储备缺口可直达对应远征收益榜，远征详情反查会推进的遂行中任务，
编队抬头反查当前阵容满足的任务编成条件；活动机关清单按海域、难度和资料版本保存手动进度。
游戏抬头同时显示舰娘/装备仓库容量，接近上限时高亮，并可直达清理视图；
入渠与建造坞并排常驻，建造分「建造中（倒计时）」与「完成待领」两种状态，
悬停建造坞出预览卡：通常/大型、完成时刻、现在抢完要几个高速建造材、还剩几个空坞。
默认不报造出来是谁——那是游戏要留给你点开船坞的一刻；设置里有「提前显示建造结果」开关，
开了预览卡与建造完成通知一并报名字，但抬头那格始终只写「领」，不会让你扫一眼就被剧透。
战斗页在没有出击时摆演习名簿：五个对手的军衔/等级/旗舰/打没打、刷新倒计时与生涯战绩，
快照属于上一轮刷新周期时标「记录已过期」，绝不拿旧名簿冒充当前的。
活动页会把当前四支舰队中的精确特效舰实例提到前面，并按所选目标点判断各基地航空队是否可达；
远征规划支持保护舰队、排除实例、补给后净收益和永久结算履历。任务详情按真实库存辅助选择报酬，
年任则只在任务库明确给出月份时显示倒计时并重置本地计数。

## 开发

Windows 下有两种入口：

- 正式应用外观：运行一次 `npm run package:win`，然后直接双击
  项目根目录自动生成的 `kuma` 快捷方式。它指向
  `release/kuma-win32-x64/kuma.exe`，是带 kuma 图标、无命令行窗口的便携应用目录。
- 开发入口：双击项目根目录的 `启动kuma.cmd`。它会自动进入项目目录，首次缺少依赖时
  运行安装，然后构建并启动；若启动失败，窗口会保留具体错误信息。

便携打包**只带随包箱里的矿脉资料**（`scripts/lode-sources.json` 里 `bundle: true` 的那些，
即数据本身所在的源有明确、允许再分发的许可的包）。本机抓过的其余资料不会进产物。
过滤在 `scripts/lib/package-ignore.mjs`，名单的唯一出处是 `scripts/lib/bundled-lodes.mjs`，
`.gitignore` 的反选块由 `npm run lodes:sync-ignore` 从同一份生成，测试跑 `--check` 挡漂移。
给随包箱加包之前先把许可核实清楚，并在 `NOTICE.md` 里署名（有测试挡着，忘了会红）。

```bash
npm install
npm run lodes:fetch   # 拉取社区数据包（显式联网，见下）
npm run lodes:reconcile # 对账 wikiwiki 事实层、游戏 API 与 kcwiki 兜底
npm run lodes:localization # 只批量更新汉化包（舰娘/装备/深海/海域/道具）
npm run lodes:map-intel-limited # 限定期台账 × 上游总表的对照报告（只读，不写包；--offline 可跳过联网）
npm run lodes:map-intel-event   # 按节奏批量刷新当前活动 E 图，四难度分层
npm run lodes:map-intel-approve # 核对差异报告后批准候选
npm run lodes:fetch -- --only=map-enemy-comps # 常规图敌编成汇编包（37 图，上游自带 mstId）
npm run lodes:fetch -- --only=map-drops       # 常规图确认掉落汇编包（37 图，同一批页面走同一份当日缓存）
node scripts/compare-map-intel-sources.mjs --air # 敌编成/掉落双源对账 + 制空值反校
node scripts/fit-bonus-reconcile.mjs # 装备加成与 EO 逐格对数（EO 只当印证票，不入仓）
node scripts/fit-bonus-votes.mjs     # 只给吵起来的装备去 wikiwiki / akashi 取票
npm start
```

- 矿脉数据包不入仓库：多数上游未声明许可，按纪律「仅用户显式拉取，不随包分发」。
  清单在 `scripts/lode-sources.json`，抓取产物落 `assets/lodes/`（已 gitignore）。
  没有数据包也能跑——相关区块会显示「待矿脉」而不是硬造数据。
  事实层按「游戏 API → wikiwiki 日文一手 → 专门化结构源 → kcwiki 中文本地化/兜底」选用；
  每次换源后用 `npm run lodes:reconcile` 输出逐项差异。KCNav 明确拒绝未授权 API 自动化，
  因此只接受 `KANSO_KCNAV_EXPORT` 指向的官方/用户手动离线包，不绕过上游限制。海域详情把
  wikiwiki 日文原表、KCNav 精确编成实测和 kcwiki 中文说明分层展示，不把自然语言或频率冒充
  游戏硬规则。抓取失败会返回非零退出码，事实源失败时也不会用旧包生成一份看似刚更新的对账。
- 装备加成（装備ボーナス）走多源汇编：随包基座是 `kcwiki-fit-bonus`
 （zh.kcwiki`模块:舰娘装备数据改`，CC BY-NC-SA，抓取时就把中文名翻成 id 空间，
  运行时零解析）；EO 的 `FitBonuses.json`（NOASSERTION）与 wikiwiki、akashi-list
  只当**对账印证票**，不入仓、不随包。字段规范见 `scripts/fit-bonus-schema.md`，
  名字词表与逐条依据见 `scripts/lib/fit-bonus-vocab.mjs`，已裁过的分歧进
  `scripts/lib/fit-bonus-conflicts.mjs` 台账（带指纹自失效，两边哪边改了数都会告警）。
  可靠性阶梯：装备后的舰娘最终面板 > 日文侧近期验证 > kcwiki > EO（2025-03 起停更）。
  运行时是双轨：查表算出的「预期值」与从面板反推的「你的实测」并列，不一致以实测为准
 （求值器与反推都在 `src/shared/fit-bonus.ts`，纯函数、单测覆盖）。已裁定的分歧不改 CC 包，
  由 `src/shared/fit-bonus-corrections.ts` 在加载时叠一层第一方补正，逐条带日文依据与
  上游行指纹；上游一改就作废并告警。上游还没收录的新装备（id > 包的覆盖上限）显示
  「暂无预期数据」+ 实测值——不等上游。akashi-list 的运行时拉取已于 2026-08-22 整层退役
 （该站未声明数据许可），`scripts/akashi-fit-parser.mjs` 只留在维护者侧取票。
- 汉化在应用内完全离线：维护者显式执行 `npm run lodes:localization`，一次批量读取
  KCWiki / kcwikizh 的舰娘、装备、深海、海域、道具和任务原文，生成
  `kcwiki-localization` 本地包。UI 以简中为主，名称旁的「原」可在原位展开日文；
  缺少可靠译名时保留原名，不在运行时调用翻译 API。装备译名直接按 KCWiki 原始模块的
  `ID + 日文名` 对齐，不消费 kcdata 已知会被同号深海装备污染的中文字段。
- 海域掉落与敌编成在应用内完全离线：低频全量重建用 `npm run lodes:map-intel`，
  期间限定高频核对用 `npm run lodes:map-intel-limited`；刷新只产生
  `assets/review/map-intel.candidate.json` 和 `assets/review/map-intel.diff.json`，
  审核后才批准覆盖正式包；审核文件不会进入矿脉扫描目录。
  活动维护配置在 `scripts/map-intel-events.json`，同一张 E 图一次请求后拆成甲/乙/丙/丁；
  各难度同时保存敌编成、确认掉落、机关条件、特效舰、友军与基地航空半径，
  开放后前 72 小时按 6 小时、第 4–7 天按每日、稳定后按 48 小时判断是否到期。
- 常规图敌编成走多源汇编（2026-08-22 换源）：随包的是第一方汇编包
  `map-enemy-comps`（`npm run lodes:fetch -- --only=map-enemy-comps`）。上游
  zh.kcwiki 的「深海配置」表逐条自带 mstId（`(1501)` 就是号），不再需要从名字猜。
  每条编成带内部印证票：kcwiki 直接填的号、现行 map-intel（wikiwiki 标注名经旧定号
  流水线定出来的号）、本机遭遇志 `encounters`。两票一致才算多源印证，**单源条目照收不丢**，
  源间互斥（同一套阵容两边给了不同阵形/经验）进 `assets/review/map-enemy-comps-conflicts.json`
  等人裁——脚本不替人拍板。印证状态只存在数据内部与维护者工具里，界面不逐条挂标。
  换源前后逐条对过：常规图 1255 条编成里 1156 条有号（92.1%）→ 1312 条全部有号，
  一条旧编成都没丢，掉落一格未动。对账用 `node scripts/compare-map-intel-sources.mjs`
 （`--air` 另拿 kcwiki 逐编成的制空值反校我们自己算的深海制空，那是印证票，不进随包层）。
  wiki 的形态标注（`軽母ヌ級改 flagship 艦載機鳥赤` 这类主数据没有的信息）与号并存在
  `labels` 里，界面照旧显示标注原文、链接用号。
  两条旧的定号流水线（`lodes:map-intel-pin` / `-observe`）随之退役——上游给号之后，
  「靠名字猜号」的存在理由消失了（有测试钉着不许加回来）。
  活动图的编成仍在 map-intel 里（旧号照旧保留）；
  新活动图若出现没有号的编成，运行时按既有的模糊命中降级显示，不猜具体形态。

  战斗预测、编成反查、图鉴一律只吃定好的号：没号的编成整条跳过，绝不在运行时按名字反解——
  同名多形态猜错一个，算出来的就是另一支敌队的胜率。
- 常规图确认掉落也走多源汇编（2026-08-22 换源，批次 2）：随包的是第一方汇编包
  `map-drops`（`npm run lodes:fetch -- --only=map-drops`）。三张票：kcwiki 的「舰娘掉落表」
 （中文舰名经 `kcwiki-ships` 解号）、现行 `map-intel` 的既有条目、本机遭遇志
  `encounters.drop_mst`。票的独立性与编成域不一样——kcwiki 的常规海域页页脚 37/37 自述
  「主要数据来源为日wiki」（原文照录进包的 `sourceNotes`），所以两 wiki 一致只算
  「同源转录」，只有账本票才算真正独立的第二票。单源条目照收不丢（5-6 那 473 条、
  7-5 那 323 条不归零）。换源前后逐条对过：丢失的原有掉落条目 0 条，新增 63 条全部来自
  kcwiki 的覆盖增量，10788 → 10851 舰次。中文舰名解不出 mstId 一律**硬错拒绝出包**，
  不静默丢（2026-08-11「杉@1-5 被静默丢掉」的教训）。待裁项进
  `assets/review/map-drops-conflicts.json`。
- 限定期窗口做成第一方手工台账（2026-08-22 换源，批次 4）：随包的是
  `assets/lodes/map-drop-windows.json`——`FIRST_PARTY_LODE_IDS` 的头一个住户，
  入仓、随包、抓不回来（不在 `lode-sources.json` 里，`lodes:fetch` 一行都不动它）。
  这一格穷举过的社区机读源只剩一家，而那家的许可不允许随包分发；所以事实自己记一份台账
  （哪张图哪个点从哪天起掉哪条船，是运营行为事实），`npm run lodes:map-intel-limited`
  降为维护者侧对照工具（`eo-quests` 地位）：读上游只出差异报告，一个字都不写进
  `assets/lodes/`。迁移前后逐条对过：**144 条一格不丢**（92 条 `limitedOnly`、2 条带往期窗口，
  三态分布 134 无截止日 + 10「上游不再列出、日子不明」）。每条带 `evidence`
  （官方公告 / 本机实测 / 社区资料整理，后者写明只作参考）与印证票，缺凭据的整包拒收。
  批次 2 的 7 条 `limited-vs-plain` 照旧挂 `conflict` 待裁，这一次不代拍。
  报告另给一条账本信号：「疑似已收窗」——自从上次捞到它，这张图又 S 胜了 N 次都没再出
  （只对本机捞到过的条目成立、按图归不按点，是线索不是判据，只进维护者侧，不进玩家 UI）。
- 限定期结束后本机确认层永不删除，只换语境（用户 2026-08-22 拍板）：
  「你在这里捞到过」是永真的历史事实。最近一次捞到的日子落在已收窗的窗口里，
  就挂「限定期捞到 · 窗口已结束」折进往期，不再混在面向当下的清单里；落在开窗/无截止的窗口里
  （常规图的常态）原样显示。窗口关了之后**又**捞到过的仍然算当下——那正说明它其实还在掉，
  台账那一条该被重核。判据是纯函数 `shared/limited-window.ts` 的 `localDropEraOf`，
  运行时与维护者脚本共用同一份。
- 本机确认掉落层与离线目录**并列显示，不合并**：出击卡的「当前点掉落」与海域详情的
  「确认掉落」都分成「你的实测」与「确认目录」两段，跟敌方编队卡同一个排法。
  聚合在主进程（`src/main/mg/local-drops.ts`，纯函数、单测覆盖），
  数据来自永久表 `encounters`——合并会让第一方观测冒充社区确认，那是两种不同强度的证据。

  矿脉包不入仓库（第一方台账 `map-drop-windows` 除外，它随源码走）：
  换机器或重新克隆后要重跑一次抓取 → 批准。
  上游名单里消失的限定条目**只转状态、不删除**；核实结束日期后用
  `npm run lodes:map-intel-confirm-end -- <海域> <舰娘ID> <YYYY-MM-DD> "<凭据>"`
  就地改台账（对照报告会把它列成 `ledger-only` 提醒你，但写不写、写哪一天由人裁，
  且必须写凭据）。台账入仓，`git diff` 就是那道逐行审阅闸。
  活动结束时先把活动配置的 `status` 改为 `ended` 并填写 `until`，再运行
  `npm run lodes:map-intel-event-end` 冻结归档。维护或新阶段需要立刻复查时可为刷新命令加 `--force`。
- 代理配置在设置面板，或直接改 `%APPDATA%/kuma/config.json` 的 `proxy` 节；
  保存后即时应用，面板显示应用结果与登录 Cookie 最近落盘状态。
- `KANSO_DEVTOOLS=1` 打开壳 DevTools；`KANSO_SMOKE=1` 启动 10 秒后自动退出（冒烟测试，
  用独立的 `%TEMP%/kanso-smoke` 数据目录，与正式实例零锁竞争）。冒烟不只看窗口起没起来：
  任务树要渲染出真实节点，模块装配账要报满（`modules 10/10`）且无模块崩溃，缺一不算通过。
- 退出不许留孤儿：`npm run quit:e2e` 在打包产物上真关一次窗口，断言同映像进程清零，
  并覆盖「游戏渲染进程卡死时关窗」这个历史现场。它用 `KANSO_DATA_DIR` 把数据目录指到
  临时副本（`KANSO_QUIT_TRACE=1` 打开退出流水），绝不碰正式账本，也不会去动正式实例。
  查「kuma 在不在跑」的判据是**命令行带不带 `--type=`**：不带的才是主进程，
  只剩带 `--type=` 的说明全是上次漏下的孤儿，清掉即可（`npm run package:win` 已内置这道检查）。
- 崩溃只黑一格：十几个模块共用一个渲染进程，从前内核派发与模块装配都是裸调用——
  一个模块抛异常，排在它后面的全部收不到更新或干脆装不上，表现为界面卡死或黑屏。
  现在内核派发逐个隔离、模块装配逐个隔离，坏掉的那格就地显示错误原文与「重试装配」，
  顶栏出 `⚠` 角标可翻本次全部记录。所有记录（含主进程未捕获异常、渲染进程结束原因）
  写入 `%APPDATA%/kuma/crash.log`，只留本机、不上传，设置面板「运行诊断」可直接打开。
- 游戏静态资源缓存/魔改放 `%APPDATA%/kuma/MyCache/KanColle/`，`.hack.<ext>` 变体优先。
- 数据落盘：`%APPDATA%/kuma/` —— 事件账本 `mg.sqlite`（默认永久保留；设置里可自设
  保留天数或按月清理，遭遇志/任务进度/舰娘人生记录任何清理都不碰）、状态快照 `snapshots/`、
  矿脉用户包 `lodes/`、崩溃日志 `crash.log`（超过 512KB 只保留后半段）。
  设置面板可单独备份、校验并恢复履历数据库。
