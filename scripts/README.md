# scripts/ — 维护者侧脚本

这一层**永不进发行产物**。玩家侧的「零第三方请求」红线靠的是产物里根本没有这些代码，
不是运行时判断——所以任何需要外部 API 的活都只能长在这里。

---

## ASR 转写管线

拿阿里云百炼（DashScope）给语音域做转写：把语音档案里的实物音频转成日文，
再与「所称文本」对账，或给没有上游文本的格子出草稿。

### 三条铁律

1. **纯维护者侧。** 密钥只从环境变量 `DASHSCOPE_API_KEY` 读，绝不入仓、绝不落盘、绝不打日志。
   `scripts/lib/asr-client.mjs` 是唯一的调用口，别在别处再开一个。
2. **产出是草稿层（`asr-draft`），权威低于人肉转写。** wikiwiki / kcwiki 的誊写一到就替换或仲裁。
   一切产出带来源标进维护者侧台账或审稿单，**绝不直接进随包数据**。
3. **机器印证是候选，不是结论。** 对账报告里的「可疑」只是耳测候选，
   人裁过才允许进 `voice-playback-observations`。脚本自己不写台账。

报告落在 `assets/review/asr-audit.{json,md}`，两者都已被 `.gitignore` 挡住——
里面是日中对照的参考材料，按台词域 2026-08-22 的口径**只能待在本机**。

### 用法

```bash
node scripts/asr-audit.mjs --dry-run          # 只算条数/秒数/预算，一分钱不花
node scripts/asr-audit.mjs --one=445:1        # 只跑一条（mstId:槽位），样张用
node scripts/asr-audit.mjs --limit=5          # 只跑前 5 条
node scripts/asr-audit.mjs                    # 全跑；已转写的读缓存，不重复花钱
node scripts/asr-audit.mjs --refresh          # 强制重转写（会重新花钱）
node scripts/asr-audit.mjs --model=fun-asr-flash-2026-06-15
```

断点续跑：结果按 `文件名 + 模型 + 偏置词` 缓存在 `%APPDATA%\kanso\asr-cache.json`
（**在仓库外**）。网络失败与转写被拒**不进缓存**，下次还会重试；两者在报告里分开记。

### 选型：为什么是 base64 直传

2026-08-23 实测：

| 路子 | 结论 |
| --- | --- |
| fun-asr **录音文件识别** `/api/v1/services/audio/asr/transcription` | 只收公网 HTTP(S) URL，本地文件与 base64 都不认。走它就得挂 OSS——为几十条几秒钟的 mp3 引入对象存储，代价不成比例，**不用** |
| fun-asr **多模态生成口** `/api/v1/services/aigc/multimodal-generation/generation` | 认 `data:audio/mpeg;base64,…`，mp3 直传成功，额外给逐字时间戳 |
| qwen3-asr-flash **OpenAI 兼容口** `/compatible-mode/v1/chat/completions` | 认 base64，**且支持 system 消息做专名偏置**——默认用它 |

所以**不需要 ffmpeg 转码**，mp3 原样上传即可；ffmpeg/ffprobe 只用来量时长算预算，
没装也能跑（退回按码率粗估，宁可估高）。

计价 ¥0.00022/秒（fun-asr 北京地域），按秒进位。全档案 21 条 96 秒 ≈ **¥0.023**。

### 专名偏置比后处理重要得多

舰C 专名（舰名/舰种/装备）是 ASR 的必然短板。2026-08-23 拿秋津洲 1 号槽做的对照
（同一条音频，模型输出**确定性**，重复两次逐字相同）：

| 偏置词 | 转写 | 相似度 |
| --- | --- | --- |
| 无 | 水上**規模感**、**秋篠**よ。この**大抵**ちゃんと一緒に覚えてよね。 | 0.760 |
| 身份词（秋津洲/水上機母艦） | 水上機母艦秋津洲よ。この**大提督**一緒に覚えてよね。 | 0.800 |
| 身份词 + 装备（二式大艇/大艇ちゃん） | 水上機母艦秋津洲よ。この大艇ちゃんと一緒に覚えてよね。 | **1.000** |

所称原文：`水上機母艦、秋津洲よ！ この大艇ちゃんと一緒に覚えてよね！`（相似度按归一后算，标点不计）

两条由此定下：

- **偏置词表决定成败**，后处理纠偏只是第二道网。同音异字（秋津洲→秋篠）与所称词的
  字符相似度只有 0.33，想靠后处理拉回来，阈值必须低到会把句子里任何两字词都改成专名。
  所以 `correctProperNouns` 只捞「差一个字」的近失，捞不动的如实标 `unfixed` 交给人耳。
- **别放通用词。** 偏置里带「提督」之后，模型把原本转对的「大艇ちゃん」写成「大提督ちゃん」——
  通用词本来就是 ASR 最不会错的一类，放进去毫无收益，却给了模型把邻近音节往它身上拉的理由。

### 对账场景下偏置不能抄答案

拿「所称日文」去偏置、再回头拿转写跟它算相似度，是让模型照着答案抄一遍：分数必然虚高，
而对账的全部意义就是让分歧显形。所以 `biasTermsOf` 只给**身份词**——
「这一条是谁在说」是从 pathname 反解出来的独立事实，不是从待验文本来的。

装备名（如 `二式大艇`）来自 `api_mst_slotitem` 主数据，同样与待验文本无关，
**可以**用；但「哪件装备与这一句相关」目前没有非循环的判据，是待定的设计题。
②③ 的草稿转写没有所称文本可抄，届时可以放宽，另行标定。

### 归属是从 pathname 反解的

档案索引里 `mstId` / `voiceId` 一律是 0——入档走的是 `voice-probe` 的
`keepVoiceBlob({ pathname, version, bytes })`，那条路径根本没有归属参数。
所以归属靠反解，判据与 `src/shared/voice-sound-path.ts` 的文件头同源：

```
目录 = 'kc' + api_mst_shipgraph.api_filename
编号 = lineNum ≤53 时 (mstId+7)*17*VOICE_KEYS[lineNum-1] % 99173 + 100000，54 起裸编号
```

反解是**枚举**：按目录取候选 mstId，逐个正推 1..53，撞上哪个就是哪个槽。
所称文本取 `subtitle-ja`（按槽位号直接索引，不必过 kcwiki 的场景 token 表）。

### 护栏

`test/asr-normalize.test.mjs` 钉住归一/相似度/纠偏三组纯函数。
这一层的错**不报错**：判断写反了只会让相似度整体偏移，于是可疑条目排不到前面，
人去耳测时先听到的全是好条目——症状不像 bug，所以用例大半拿实测的真实字串钉。
